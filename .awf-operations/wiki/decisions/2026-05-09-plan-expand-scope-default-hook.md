# Decision

The plan SKILL now treats `awf wf expand-scope --direction dependents` as the default post-`allowed-files.json` hook before G1, with no-op semantics when no analysis graph or no extra dependent files exist.

## Context

`allowed-files.json` starts from `tasks.md` paths, which are generated by the plan skill and can omit direct consumers of changed files. That omission produces G5 `SCOPE_VIOLATION` false positives when `awf wf scope-check` compares the implementation diff against `planned_files ∪ expanded_files`.

PR #32 had already made operations wiki compilation deterministic, and PR #34 had aligned `.ai-context` markdown outputs with deterministic metadata. The remaining workflow gap was that graph expansion existed as a CLI command but was still documented as optional in the plan phase. The operationally useful default is to run it every time and let the command fall through cleanly when no graph is available.

## Options considered

- **Option A — make the phase-plan SKILL run `expand-scope --direction dependents` by default** (chosen): small surface change; preserves the existing CLI contract; captures the value where the workflow already creates `allowed-files.json`. The tradeoff is that external plan generators that do not follow the skill will not get automatic expansion.
- **Option B — make `awf wf gate plan` invoke expansion automatically**: stronger enforcement for all callers, but it would make a gate command mutate workflow artifacts. That violates the current deterministic gate boundary, where `gate plan` evaluates and reports but does not rewrite state.
- **Option C — add a new finalize/sync command that creates allowed files, expands scope, and runs G1**: a cleaner long-term interface if non-skill plan generators become important. It is larger than the current need and would introduce another workflow command before there is enough pressure for it.

## Decision rationale

Option A is the narrowest change that removes the known false-positive source from normal skill-driven workflows. `awf wf expand-scope` already handles missing graphs as a normal empty result, so making it the default hook does not force projects to run `awf analyze` first.

Keeping `awf wf gate plan` read-only matters more than centralizing this behavior in the gate. Gate commands are used as deterministic validators; making them rewrite artifacts would hide state changes behind a command whose name and existing docs imply evaluation only.

The default direction is `dependents`, not `both`, because the main G5 false-positive case is downstream consumers of an edited file. Pulling imports into scope by default can broaden implementation permissions more aggressively and should remain an explicit manual choice.

## Consequences

- **Now**: phase-plan guidance runs graph expansion before G1; docs describe no-graph/no-addition cases as normal no-ops instead of optional skips.
- **Locks-in**: `expanded_files` is part of the normal skill-produced execution contract, while `gate plan` remains an evaluation-only command.
- **Revisit when**: non-skill plan generators become common, or users need automatic expansion even when the phase-plan skill was not involved. At that point Option C should be reconsidered before mutating `gate plan`.
